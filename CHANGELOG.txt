2026:08:21

- Underscore is now a real "ignore this" convention instead of just erroring on reuse. '_'
  and anything starting with '_' skips the same-scope redeclaration check, so this works now:
  ```
  buf, _, _ := some_call_returning_three_things();
  fn parse(_ctx: *void, data: string) -> i32 { ... }
  ```
  Previously 'buf, _, _' errored as a redeclaration of '_' the second time.

- 'main' must be declared 'pub' now, or it's a hard compile error. The NASM backend only ever
  emitted a 'global' directive for pub functions, so a non-pub main quietly had no linkable
  entry point. Rather than silently forcing it pub behind your back, we just tell you.

- Fixed 'cannot take the address of this expression' being the same unhelpful line for every
  case. It now says what it actually saw, e.g. 'cannot take the address of a binary expression:
  it has no storage location, so '&' has nothing to point at'.

- Returning a slice of a local array finally works, with an actual safety story behind it
  instead of just making it compile:
  ```
  fn foo() -> []i32 {
      x := [22, 23, 44];
      return x;   // legal: x has no mutations anywhere in foo, so it's promoted
                  // to a static .data global instead of a stack slot.
  }
  ```
  If the array gets mutated anywhere in the function (or is built from runtime values), it
  can't be promoted, and returning a slice of it is now a hard compile error telling you to
  either return a dynamic array ('[..]T') or take a caller-supplied output buffer instead of
  silently handing back a dangling pointer into a stack frame that's already gone.

- Real type aliasing, finally, via a new 'using' declaration:
  ```
  using StringBuilder = [..]char;
  x : StringBuilder;
  ```
  This replaces the old trick of writing 'Name :: OtherType;' and hoping the const-decl code
  noticed the right-hand side was itself a type name that only ever worked when aliasing one
  bare existing type to another, never for an actual type expression like a pointer, slice, or
  fn-type. 'using' takes any type expression. The old '::' special case has been removed
  entirely now that there's one real mechanism instead of two overlapping ones.

- Cross-module type references work now, both bare and qualified:
  ```
  #import "error";
  fn openFileDescriptor(path: string) -> (i32, ioError) { ... } // bare: ioError from the
                                                                // 'error' module, works
                                                                // because this file imports it
  x : error.ioError; // qualified, from anywhere, same syntax expressions already use
                     // for alias.member
  ```
  Both directions of this were previously unimplemented for types specifically (functions/
  consts/globals already worked bare and qualified; types didn't do either).

- Using now does not require an '=' sign after the name.

- Type parametrization will now have type constraint in a generic template function.
  ```
  fn foo(x: $T(*u8 | string)) {
  }
  ```
  This will limit the type of x to be of a u8 pointer or a string.

2026:08:31

- Fixed a real codegen/scope bug in the `#comptime` bytecode compiler (`st_comptime_compile.c`):
  `&out.capturedStdout`-style address-of on a struct field was being rejected with a generic
  "can only take the address of a plain local name or an indexed element of a zero-initialized
  array local" error. This wasn't a misfire; the `#comptime` VM represents struct locals as
  boxed values with no real byte address to hand out, so there was genuinely nowhere for the
  address to point.

- First pass: added general pointer dereference support to the `#comptime` compiler, which
  didn't exist at all before this (`*ptr` as a read, and `*ptr = value;` as an assignment,
  for int/pointer/string pointee types). Added two new bytecode ops, `ST_OP_PTR_LOAD_STR` /
  `ST_OP_PTR_STORE_STR`, since `string` is a 16-byte `{data_ptr, len}` fat pointer that the
  existing int-only `PTR_LOAD`/`PTR_STORE` couldn't move through memory. Made `&structlocal.field`
  legal as a direct call argument via copy-in/copy-out: allocate a scratch buffer, seed it with
  the field's current value, pass its address, read it back, and write it into the struct field
  once the call returns. Known limitation at this point: only worked as a direct call argument,
  not stored in a variable or returned, and only for `string` and plain-int fields.

- Second pass: removed the copy-in/copy-out hack entirely in favor of making struct locals (and
  struct-typed parameters) genuinely buffer-backed in the `#comptime` VM, the same way arrays
  already were, instead of boxed values with no address. A struct's "value" is now just its
  address. This is what actually fixes the "stored in a var / returned / nested" limitations:

  - `&x.y.z` now works at arbitrary nesting depth, through structs and through fixed-size array
    fields (`&s.items[i].field`), and produces a real, persistent pointer usable anywhere, not
    just as an immediate call argument.

  - Added a new op, `ST_OP_MEM_COPY`, and used it to preserve by-value copy semantics everywhere
    it matters now that structs are addresses under the hood: `d := c;`, passing a struct by
    value into a function, `x.field = other_struct;`, and `return some_struct;` all do a real
    byte copy into independent storage now, instead of the two locals silently aliasing the same
    memory.

  - Struct literals, including nested struct-typed fields inside a literal, compile straight into
    a buffer instead of the old boxed `MAKE_STRUCT`/`GET_FIELD`/`SET_FIELD` representation. Those
    ops are left in place in the VM (unused by the compiler now) rather than ripped out, since
    plain bracket/array literals (`[a, b, c]`) still use the same boxed representation and share
    the opcodes.

  - Known remaining gaps: a fixed-size array field can't be initialized inline via a bracket
    literal inside a struct literal yet (declare it plain and fill it with a loop instead, since
    that path works). Also, `#comptime` scratch memory is a single fixed-size region that's never
    reclaimed (true before this work too, for zero-init locals), so a `#comptime` loop doing
    heavy struct work can still exhaust it.

- None of the above touches the real (non-comptime) NASM/FASM backends or the SSA lowering pass;
  this was scoped entirely to the `st_comptime*` bytecode VM and its compiler, since that's
  what actually executes `#comptime` blocks and `storthc run`.

## Module API notes

Documenting the current shape of the module system, since it came up while working on the
above and it's easy to lose track of:

- Modules live as `.st` files and are pulled in with `#import "name"`. Cross-module references
  (functions, consts, globals, and now types too, see 2026:08:21) work both bare (if the
  importing file itself imported the defining module) and qualified (`module.Member`, from
  anywhere).

- OS/syscall-specific code is intentionally kept out of the portable modules and centralized:
  each supported OS has its own `module.st` (currently just Linux) holding the actual syscall
  numbers, register-argument wiring, and other platform asm, so the portable modules (`process`,
  `io`, `mem`, `array`, `time`, `error`, ...) can stay platform-agnostic at the API level and
  just call into the OS module underneath.

- Practical consequence: every module file is different, not just in what it exposes but in how
  documented it is. The OS module in particular is barely documented on its own terms, since reading
  it productively currently requires already knowing the target OS's syscall table, since the
  file itself doesn't re-explain syscall numbers/semantics inline.

- `mem` (arena/heap alloc, realloc) and `array` module interfaces exist but are still described
  as basic/helper-level as of 2026:08:16; `static` and `using`-based interface updates for `mem`
  were called out as not yet implemented at that point.

- No CI coverage of examples/test cases yet as of 2026:08:29. They exist and are useful for
  manual bug-hunting, but aren't wired into the pipeline added that same day.

- 'file' now uses the sys_ naming correctly. More functions are update.

- Comptime has if switch statment and also not only that but also it now can do field access on
  arbitrary struct. Comptime has named parameter the previous bug of which we can not have as the
  address is not lowered.
