# Storth Programming Language

2026:11:23
- Lambdas: `fn(x: i32) -> i32 { return x * 2; }` is now an expression. The parser hoists each one to an ordinary
  top-level function with an unspellable name (`main$lambda$1`, or `parent$lambda$N` inside another function) and the
  expression becomes a reference to it, so it is a plain function pointer and semantic analysis, lowering and the
  backends needed no changes. A statement that starts with `fn(` is a lambda, `fn name(` is still a nested function.
- A lambda can be assigned, passed, called where it is written (`fn(x: i32) -> i32 { .. }(3)`), stored in struct
  fields and arrays, returned, nested, and written in nested functions, generic functions, trait witnesses, modules
  and `defer`.
- Untyped parameters, default values, generic parameters and a missing body in a lambda are errors.
- Closures: a lambda or nested fn can have a capture list after its signature, `fn(x: i32) -> i32 |a, &b| { .. }`.
  `a` is copied when the lambda is written and is read only (assigning to it is an error), `&b` is captured by
  reference, so the body reads and modifies the original. Nothing is captured implicitly: using an outer variable that
  is not in the list is "use of undeclared identifier" plus a note showing the list.
- How: semantic analysis, the first pass that knows the captured types, synthesizes a struct `NAME$env` with a field
  per capture (the value, or a pointer for `&b`), gives the hoisted function that struct as a hidden first parameter,
  starts its body with `a := env.a;` and turns every use of `b` into `*env.b`. The lambda expression becomes the
  literal `NAME$env { a = a, b = &b }` and `f(3)` on such a value becomes `NAME(f, 3)`.
- A closure is an ordinary struct value: copy it, store it in a local, pass it to a `$T` parameter. Its own type can't
  be spelled, but `closure(x: i32) -> i32` can: it is the type-erased form, a struct `{ call, env }` holding the
  hoisted function and up to 64 bytes of captured data inline. Anything with that signature converts to it where a
  value of that type is expected (arguments, `:=` with a type, assignment, return, struct fields, array elements): a
  closure with by-value captures, a plain lambda or any `fn(..)` value. Calling it is `f(3)`, which becomes
  `f.call(&f.env, 3)`, so the callee must be a variable, field or element. It returns at most one value.
- `closure(..)` owns its captures, so it can be returned, stored and copied freely. A closure with a `&b` capture only
  converts to the borrowing form `closure&(..)`, which also accepts everything `closure(..)` does. The compiler
  rejects returning, storing through a pointer, slice or global, or keeping in a `static` a value whose type is, or
  contains, a by-reference closure or a `closure&(..)`, because it points into the frame that wrote the lambda. The
  check follows types, not data flow, so a callee that returns a `closure&(..)` parameter is caught but a closure
  smuggled out through an `any` or a `*void` is not.
- A closure is still not a function pointer: `fn(..)` has no room for the captured data, so a closure can't be
  assigned to a `fn(x: i32) -> i32` variable or struct field, or returned as one. Write that type as
  `closure(x: i32) -> i32`; a plain `fn(..)` value converts to that, so one signature accepts both.
- A capture can be a value written in the list instead of an existing variable: `fn(x: i32) -> i32 |a: i32 = 1, b: i32 = 2| { .. }`.
  `name: type = value`, `name := value` and `name = value` (type taken from the value) are copied into the closure like a
  by-value capture, so the result still converts to `closure(..)`; they can be mixed with `|x, &y|`. The value is
  evaluated where the lambda is written and can use the enclosing function's variables. `&name = value` is an error. A
  bare `|` ends the list, so write bitwise or inside parentheses: `|mask: u32 = (A | B)|`.
  `tests/18-capture-init.st`: run `tests/set.sh 18-capture-init.st` to record its snapshot.
- A function parameter written `f: fn(x: i32) -> i32` takes a closure too. The parser reads it as the borrowing
  type `closure&(x: i32) -> i32`, which accepts a plain function, a lambda and a closure with by-value or by-reference
  captures, and `f(3)` is called the same way. Because the parameter is now a closure, inside the function it can be
  called and passed on to another such parameter, but not stored in a `fn(..)` field, returned as a `fn(..)` or
  passed to an extern C function: declare the parameter as `closure(..)` to store or return it. Left as a plain
  function pointer: signatures that mention a generic parameter (`fn(x: $T) -> $T`), `#comptime` functions, methods
  inside a trait implementation, `::` parameters, and `fn` types that are variadic, noreturn or return more than one
  value. `tests/17-fn-param-closure.st`: run `tests/set.sh 17-fn-param-closure.st` to record its snapshot.
- Writes to a by-value capture are checked by type: assigning to `s.ptr[0]` or `p.x` where the path goes through a
  pointer, slice or dyn array reaches shared memory and is allowed; `s.arr[0] = x` on a copied array is the error.
- A by-reference capture can be assigned by a multiple assignment: `a, b = f()` and `a, b = b, a` are rewritten to
  temporaries followed by plain assignments.
- `fn name(..) |a| { .. }` inside a function is sugar for `name := fn(..) |a| { .. };`. `name` is a local holding the
  closure, so it can't call itself.
- A capture list works inside a generic function (the lambda is cloned for every instantiation, so `$T` can be used
  in its body and captured variables may have generic types) and on a generic nested function,
  `fn add(x: $U) |&total| { .. }`. Still not allowed: on a top-level function, on a generic nested function written
  inside another generic function, and in a `#comptime` scope, where the VM can't pass a struct argument to a
  function yet.
- A lambda can call the nested functions written in the same block by bare name. A nested fn that contains a lambda
  is now hoisted before it, so the enclosing function is checked first.
- `tests/14-lambda.st`, `tests/15-closure.st`, `tests/16-closure-types.st`: run
  `tests/set.sh 14-lambda.st 15-closure.st 16-closure-types.st` to record their snapshots.

  file, line and column. It replaces `#code`. The value has the builtin type `Source_Code_Location` with the
  fields `filename: string`, `line: i32` and `column: i32`.
- Fixed call lowering for a defaulted location argument: the synthesized value was untyped and failed with
  "this expression form isn't lowered yet".
- `Io` now has `modules/Io/log.st`: `print`, `println`, `eprint`, `eprintln`, `todo` and `log_error`. They use
  Rust style `{}` placeholders (`{{` and `}}` escape braces) over `any` type records and write with the raw
  `write` syscall, no libc. `todo` and `log_error` print `file:line:column: ERROR: message` to stderr and exit 1.
- `fs.read` and `fs.write` go through the witness's own `open` and `close`.
- DWARF: base type sizes above 255 are clamped, which silences the nasm "byte data exceeds bounds" warning.
- Output is buffered like Rust's BufWriter: literal runs and strings are copied with one `rep movsb`, writes of a
  full buffer or more bypass the buffer, and `write_all` retries partial writes and EINTR.
- New IR op `ST_IR_MEMSET_ZERO` (`rep stosb`). Zero-initializing a local array of more than 8 scalar, string,
  slice or nested array elements no longer runs a byte-by-byte loop, so `o : Out` with a 1024 byte buffer stops
  costing about 36k instructions per call. Two million `println` calls went from 7.8s to 2.4s.

- `any` is now a real type: a 16 byte struct of `info: *Type_Info` and `data: *void`. Any value converts
  to it implicitly (declarations, assignments, arguments, returns, struct fields and array elements):
  `x : any = 2; x = "string";`. The value is copied into a stack slot and `data` points at it, the
  type record is static data in `.rodata`. `x.info.name` tells the type, `cast(T) x` reads the value
  back without checking, so compare `x.info.name` first. An `any` must not outlive the function that
  created it. Globals of type `any` and default values for `any` parameters are rejected.
- `ST_IR_CONST_TINFO` and per module type records in all backends.
- Calling a method with two or more plain overloads no longer skips a generic variadic overload.

2026:08:21

- Underscore is now a real "ignore this" convention instead of just erroring on reuse. '_'
  and anything starting with '_' skips the same-scope redeclaration check, so this works now:
  ```
  buf, _, _ := some_call_returning_three_things();
  fn parse(_ctx: *void, data: string) -> i32 { ... }
  ```
  Previously 'buf, _, _' errored as a redeclaration of '_' the second time.

- 'main' must be declared 'pub' now, or it's a hard compile error. The NASM backend only ever
  emitted a 'global' directive for pub functions, so a non-pub main quietly had no linkable
  entry point. Rather than silently forcing it pub behind your back, we just tell you.

- Fixed 'cannot take the address of this expression' being the same unhelpful line for every
  case. It now says what it actually saw, e.g. 'cannot take the address of a binary expression:
  it has no storage location, so '&' has nothing to point at'.

- Returning a slice of a local array finally works, with an actual safety story behind it
  instead of just making it compile:
  ```
  fn foo() -> []i32 {
      x := [22, 23, 44];
      return x;   // legal: x has no mutations anywhere in foo, so it's promoted
                  // to a static .data global instead of a stack slot.
  }
  ```
  If the array gets mutated anywhere in the function (or is built from runtime values), it
  can't be promoted, and returning a slice of it is now a hard compile error telling you to
  either return a dynamic array ('[..]T') or take a caller-supplied output buffer instead of
  silently handing back a dangling pointer into a stack frame that's already gone.

- Real type aliasing, finally, via a new 'using' declaration:
  ```
  using StringBuilder = [..]char;
  x : StringBuilder;
  ```
  This replaces the old trick of writing 'Name :: OtherType;' and hoping the const-decl code
  noticed the right-hand side was itself a type name that only ever worked when aliasing one
  bare existing type to another, never for an actual type expression like a pointer, slice, or
  fn-type. 'using' takes any type expression. The old '::' special case has been removed
  entirely now that there's one real mechanism instead of two overlapping ones.

- Cross-module type references work now, both bare and qualified:
  ```
  #import "error";
  fn openFileDescriptor(path: string) -> (i32, ioError) { ... } // bare: ioError from the
                                                                // 'error' module, works
                                                                // because this file imports it
  x : error.ioError; // qualified, from anywhere, same syntax expressions already use
                     // for alias.member
  ```
  Both directions of this were previously unimplemented for types specifically (functions/
  consts/globals already worked bare and qualified; types didn't do either).

- Using now does not require an '=' sign after the name.

- Type parametrization will now have type constraint in a generic template function.
  ```
  fn foo(x: $T(*u8 | string)) {
  }
  ```
  This will limit the type of x to be of a u8 pointer or a string.

2026:08:31

- Fixed a real codegen/scope bug in the `#comptime` bytecode compiler (`st_comptime_compile.c`):
  `&out.capturedStdout`-style address-of on a struct field was being rejected with a generic
  "can only take the address of a plain local name or an indexed element of a zero-initialized
  array local" error. This wasn't a misfire; the `#comptime` VM represents struct locals as
  boxed values with no real byte address to hand out, so there was genuinely nowhere for the
  address to point.

- First pass: added general pointer dereference support to the `#comptime` compiler, which
  didn't exist at all before this (`*ptr` as a read, and `*ptr = value;` as an assignment,
  for int/pointer/string pointee types). Added two new bytecode ops, `ST_OP_PTR_LOAD_STR` /
  `ST_OP_PTR_STORE_STR`, since `string` is a 16-byte `{data_ptr, len}` fat pointer that the
  existing int-only `PTR_LOAD`/`PTR_STORE` couldn't move through memory. Made `&structlocal.field`
  legal as a direct call argument via copy-in/copy-out: allocate a scratch buffer, seed it with
  the field's current value, pass its address, read it back, and write it into the struct field
  once the call returns. Known limitation at this point: only worked as a direct call argument,
  not stored in a variable or returned, and only for `string` and plain-int fields.

- Second pass: removed the copy-in/copy-out hack entirely in favor of making struct locals (and
  struct-typed parameters) genuinely buffer-backed in the `#comptime` VM, the same way arrays
  already were, instead of boxed values with no address. A struct's "value" is now just its
  address. This is what actually fixes the "stored in a var / returned / nested" limitations:

  - `&x.y.z` now works at arbitrary nesting depth, through structs and through fixed-size array
    fields (`&s.items[i].field`), and produces a real, persistent pointer usable anywhere, not
    just as an immediate call argument.

  - Added a new op, `ST_OP_MEM_COPY`, and used it to preserve by-value copy semantics everywhere
    it matters now that structs are addresses under the hood: `d := c;`, passing a struct by
    value into a function, `x.field = other_struct;`, and `return some_struct;` all do a real
    byte copy into independent storage now, instead of the two locals silently aliasing the same
    memory.

  - Struct literals, including nested struct-typed fields inside a literal, compile straight into
    a buffer instead of the old boxed `MAKE_STRUCT`/`GET_FIELD`/`SET_FIELD` representation. Those
    ops are left in place in the VM (unused by the compiler now) rather than ripped out, since
    plain bracket/array literals (`[a, b, c]`) still use the same boxed representation and share
    the opcodes.

  - Known remaining gaps: a fixed-size array field can't be initialized inline via a bracket
    literal inside a struct literal yet (declare it plain and fill it with a loop instead, since
    that path works). Also, `#comptime` scratch memory is a single fixed-size region that's never
    reclaimed (true before this work too, for zero-init locals), so a `#comptime` loop doing
    heavy struct work can still exhaust it.

- None of the above touches the real (non-comptime) NASM/FASM backends or the SSA lowering pass;
  this was scoped entirely to the `st_comptime*` bytecode VM and its compiler, since that's
  what actually executes `#comptime` blocks and `storthc run`.

## Module API notes

Documenting the current shape of the module system, since it came up while working on the
above and it's easy to lose track of:

- Modules live as `.st` files and are pulled in with `#import "name"`. Cross-module references
  (functions, consts, globals, and now types too, see 2026:08:21) work both bare (if the
  importing file itself imported the defining module) and qualified (`module.Member`, from
  anywhere).

- OS/syscall-specific code is intentionally kept out of the portable modules and centralized:
  each supported OS has its own `module.st` (currently just Linux) holding the actual syscall
  numbers, register-argument wiring, and other platform asm, so the portable modules (`process`,
  `io`, `mem`, `array`, `time`, `error`, ...) can stay platform-agnostic at the API level and
  just call into the OS module underneath.

- Practical consequence: every module file is different, not just in what it exposes but in how
  documented it is. The OS module in particular is barely documented on its own terms, since reading
  it productively currently requires already knowing the target OS's syscall table, since the
  file itself doesn't re-explain syscall numbers/semantics inline.

- `mem` (arena/heap alloc, realloc) and `array` module interfaces exist but are still described
  as basic/helper-level as of 2026:08:16; `static` and `using`-based interface updates for `mem`
  were called out as not yet implemented at that point.

- No CI coverage of examples/test cases yet as of 2026:08:29. They exist and are useful for
  manual bug-hunting, but aren't wired into the pipeline added that same day.

- 'file' now uses the sys_ naming correctly. More functions are update.

- Comptime has if switch statment and also not only that but also it now can do field access on
  arbitrary struct. Comptime has named parameter the previous bug of which we can not have as the
  address is not lowered.

- Slice expressions: `base[lo..hi]` with either bound optional (`a[..n]`, `a[n..]`, `a[..]`). Works on arrays, slices,
  dynamic arrays, strings (result is a string) and pointers (needs both bounds). The result is a `[]T` header over the
  original elements, bounds are checked at compile time for constants and at run time otherwise, and `&a[lo..hi]` takes the
  address of the temporary header. Assigning to a slice expression is an error.

- `Trait(Type).method(args)`: calls a trait method through the witness of exactly `Trait(Type)` without naming it. The witness
  is searched by type, innermost scope first, two at one level is an ambiguity error, and a witness from another module is
  only used when it is `pub`. Documented in how-to chapter 22.
